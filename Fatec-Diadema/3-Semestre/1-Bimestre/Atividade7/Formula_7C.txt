O Capítulo 3 apresenta o desenvolvimento do trabalho, detalhando a origem dos dados, sua preparação e os recursos utilizados nos estudos de caso. Os dados vieram de duas fontes principais: o Instituto Nacional de Meteorologia (INMET) e o Programa de Pós-Graduação em Física Ambiental (PGFA) da UFMT. Ambos coletam informações por sensores, mas com diferenças na frequência e no volume: o INMET realiza medições horárias de temperatura, umidade, vento, radiação solar e precipitação, enquanto o PGFA coleta dados micrometeorológicos a cada segundos, gerando um grande volume de informações.

As estações meteorológicas do INMET são automatizadas e possuem subsistemas para coleta, controle, armazenamento, energia e comunicação. Elas são instaladas em áreas seguras, com mastros de 10 metros, proteção contra raios e cercadas para evitar entrada de animais. Já os dados do PGFA eram armazenados principalmente em planilhas eletrônicas, dificultando o compartilhamento, e precisaram ser convertidos para o formato JSON para permitir o processamento em larga escala.

Inicialmente, os dados foram armazenados em um SQL Server 2016, mas a geração de arquivos JSON mostrou-se lenta e ineficiente. Por isso, utilizou-se o PostgreSQL, que oferece suporte nativo a JSON, para tratar e transformar os dados. Após a conversão, os arquivos JSON foram transferidos para o MongoDB, um banco de dados NoSQL, instalado em outra máquina virtual Linux. As máquinas virtuais compartilhavam o mesmo hardware físico, mas foram configuradas separadamente para evitar conflitos entre os SGBDs.

A preparação dos dados no PostgreSQL envolveu a criação de tabelas para receber as planilhas, incluindo o atributo “fonte” para identificar a origem dos dados. Foram corrigidos formatos de data, campos nulos e linhas quebradas. Para otimizar a transformação em JSON, foram criadas tabelas auxiliares com um identificador único (id) e um campo JSON chamado “info”, que armazenava todos os outros atributos de cada registro, permitindo gerar documentos JSON de forma mais rápida e organizada.

O capítulo também detalha os equipamentos e softwares utilizados. A máquina hospedeira possuía processador Intel Core i7, 16 GB de RAM e Windows 10. Duas máquinas virtuais foram criadas com 1 núcleo de processador, 8 GB de RAM e 60 GB de HD. A VM de conversão utilizou PostgreSQL 9.6.1 e PgAdmin3 em Windows Server 2012, enquanto a VM de recepção utilizou MongoDB 3.2.8 e Robomongo em Ubuntu 16.04.

O Estudo de Caso 1 consistiu na modelagem dos dados em JSON, transformando as informações das planilhas em documentos estruturados. Cada documento possui dois conjuntos internos: KEYS, com campos-chave para identificação (fonte, ano, mês, dia, hora), e DADOS, com os atributos coletados pelos sensores. Essa modelagem flexível permitiu que o MongoDB criasse coleções automaticamente, sem necessidade de tabelas pré-definidas, facilitando o armazenamento de grandes volumes de dados temporais de diferentes fontes.

No Estudo de Caso 2, os documentos JSON foram inseridos na base do MongoDB. Antes de cada inserção, o sistema verifica se já existe um documento com os mesmos campos do conjunto KEYS. Se houver correspondência completa, o documento é atualizado; se houver campos iguais com valores diferentes, ou se não houver correspondência, um novo documento é criado. O comando utilizado foi db.teste.update com o parâmetro upsert: true, que permite atualizar ou inserir conforme necessário.

O Estudo de Caso 3 avaliou a performance dos bancos de dados PostgreSQL e MongoDB. Foram realizadas consultas simples e complexas com quatro volumes de registros: 1 mil, 10 mil, 50 mil e 100 mil. Cada consulta foi repetida 10 vezes, e o tempo médio de execução foi calculado para comparar a eficiência de cada SGBD. No PostgreSQL, as consultas simples usavam INNER JOIN entre as tabelas pgfaa e inmet, e as consultas complexas adicionavam filtros por ano e mês. No MongoDB, as consultas simples utilizavam .find({}).limit(n), enquanto as complexas aplicavam filtros diretamente nos campos JSON usando operadores como $lte e $ne.

O capítulo conclui detalhando a origem, a preparação e o tratamento dos dados, o cenário de desenvolvimento com máquinas virtuais, os sistemas operacionais e SGBDs utilizados, e descrevendo o passo a passo dos três estudos de caso: modelagem, população da base e testes de performance.
